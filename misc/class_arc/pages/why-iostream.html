Why does every file we look at start with

#include <iostream>

 

Well to understand this we have to understand what the compiler is actually doing with every "#include".

#include is simply just a compiler directive[1] that tells the compiler before it starts compiling things, it needs to copy and paste the location of the file contained inside the <>.

Yes this means that iostream is not some mystical object that cannot be explained. It can be easily found wherever your include path[2] points to.

 

Doing such gets you

#include <ios>
#include <streambuf>
#include <istream>
#include <ostream>
		
namespace std {
	extern istream cin;
	extern ostream cout;
	extern ostream cerr;
	extern ostream clog;
	
	extern wistream wcin;
	extern wostream wcout;
	extern wostream wcerr;
	extern wostream wclog;
}

What? Even more includes?! Yes, but they are easy to understand.

ios is pretty self explanatory it deals with input and output, streambuf deals with the buffers of streams, istream deals with input streams, and ostream deals with output streams.

namespace std? We've seen that before. Like before it gives the compiler the last names of the variables given below.

extern is a keyword that tells the linker[3] that this variable is not undefined and instead defined else where. (I'll explain why this is useful in a later page)

So basically this file tells the linker that the in stream std::cin, the out stream std::cout. the out stream std::cerr, the out stream std::clog, the wide[4] in stream std::wcin, the wide out stream std::wcout, the wide outstream std::wcerr, and the wide outstream std::wclog are all defined elsewhere.

 

So... Why do all this? Well to put it simply, its your choice. You have to choose to want to deal with inputs and outputs. A submarine running on C++ has no business having the extra code to print to a terminal if there is no such terminal. So for the sake of efficiency you start with nothing and pick the ingredients you want in your program.

Glossary

1. Compiler Directive - Instructions given to the compiler to preform before it starts compiling. (There's a bunch so expect a page soon)

2. Include Path - The path that the compiler looks for things like header files or libraries. Usually /path-to-compiler/include

3. Linker - The final stage in the compilation process where the compiler joins together definitions of symbols (variables and functions) into one executable file (something your cpu can run)

4. Wide Strings - A string defined with a character size larger than a byte (8 bits)
