Compiler directives are nothing more than directions for the compiler. More specifically for the Preprocessor section of the compiler.

They come in many different shapes and types depending on the compiler but for this page I will only be explaining the most common GNU GCC/G++ compiler directives.

 

The first and most common directive is the directive

#define [Name] [Value]

Now what does it do? Well simply it tells the preprocessor that wherever it sees [Name] it should replace it with [Value].

#define number 1283

int x = number; // Original code
int x = 1283; // Code after the preprocessor replaces "number"

It also has a second use in the sense that it can be used to create Macros. A macro being an automated task.

#define add5(n) (n + 5)

// Original Code
int x = add5(10);
int y = add5(0);
int z = add5(4);

// Code after the preprocessor uses the macro "add5"
int x = (10 + 5);
int y = (0 + 5);
int z = (4 + 5);

Even more interestingly you can define a name but not give it a value.

< pre>#define [NAME]

This may seem odd as you cannot use it for anything, but keep it in the back of your head.

Another directive is

#include <path/to/file>

We have already looked at this before in a previous page so I will not rehash most of the things I covered there, but this directive loads a file from an include path.

There is an important set of directives as they provide conditions

#if [Condition]
#ifdef [Name]
#ifndef [Name]
#elif [Condition]
#else
#endif

Remember how I said to keep the odd definition scheme in the back of your head, well it now comes into play.

#if only includes whatever is inside it if its condition is true (1), #ifdef does the same thing except its condition is about if Name is defined before it, #ifndef is the same as before except it wants to know if Name is not defined, and lastly #elif is just else if.

That is a lot, so lets see them in action. 

#define Val 1
#if Val
int x = 5;
#else
int x = 1;
#endif

// Because Val is 1(true) this makes the entire if block collapse into
int x = 5;

Another example

#ifndef NAME_OF_FILE
#define NAME_OF_FILE
int x = 10;
#endif

#ifndef NAME_OF_FILE
#define NAME_OF_FILE
int x = 10;
#endif

// This code seems like it should have two definitions of x
// However because we are using ifndef the second time the block
// is processed NAME_OF_FILE is defined so the condition fails
// Leaving only one definition
int x = 10;

This is useful for #include, because it lets the compiler avoid tons of redefinitions across multiple files.

There are way more than just these compiler directives, but the problem lies in the fact that most of them are compiler specific and do not work across all compilers. However because these are the most popular ones, they work nearly everywhere just fine.
