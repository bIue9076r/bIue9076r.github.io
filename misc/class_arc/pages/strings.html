Humans use words to speak, unfortunately for computers.

Previously in a latter page, we explored how words are just strings of characters.

Well what exactly does that mean?

Imagine a list of characters in the phrase "This is not a pipe"

char phrase[18] = {'T', 'h', 'i', 's', ' ', 'i', 's', ' ', 'n', 'o', 't', ' ', 'a', ' ', 'p', 'i', 'p', 'e'};

Well there are 18 letters, but only the compiler knows this not the cpu.

This is bad because if we were to read this phrase, where would we stop if we do not know how long it is? (It does not stop and goes on until it crashes)

Well why not just store how long the phrase is in a different variable.

int phrase_len = 18;
char phrase[18] = {'T', 'h', 'i', 's', ' ', 'i', 's', ' ', 'n', 'o', 't', ' ', 'a', ' ', 'p', 'i', 'p', 'e'};

Well now this works, except it is pretty clunky to work with.

stringFunction(phrase, phrase_len, ...);

It requires two arguments to be passed to be used.

Luckily for us in the modern age lots of smarter people have been working on this exact problem for ages

There are many different approaches each with their own pros and cons, but the two I will cover are the two most common methods.

Null Terminated Strings and Fat Strings.

 

Null Terminated Strings get their name from the fact that they require a Null at the end to tell the cpu that the string ends there.

char phrase[19] = {'T', 'h', 'i', 's', ' ', 'i', 's', ' ', 'n', 'o', 't', ' ', 'a', ' ', 'p', 'i', 'p', 'e', 0};

The Null (0) at the end only increases the size of the string by one byte but now we can just pass the string into any function without needing its associated length.

stringFunction(phrase, ...);

 

Fat Strings, on the other hand, get their name from the fact that they are two things at the same time.

struct fatstring_s {
	int string_len;
	char[] string;
};

struct fatstring_s phrase = {
	18, {'T', 'h', 'i', 's', ' ', 'i', 's', ' ', 'n', 'o', 't', ' ', 'a', ' ', 'p', 'i', 'p', 'e'};
};

You may have noticed that this is literally just the first method mentioned at the start, yes it very much is. However it has one notable benefit that the original method did not posses, due to the fact that you can pass the fat string as one object.

stringFunction(phrase, ...);

It gets called fat because instead of taking up one extra byte it takes up a full 8 extra bytes from the inclusion of the integer that stores its length.

There is no objectively correct answer to the storage of strings, but these few examples should be enough to get your mind jogging on how to solve the problem.

Though I should note that the C/C++ standard library runs exclusively on Null terminated strings so you should expect to turn your perfect string storage method into a null terminated string if possible.
